ทำความเข้าใจตู้เซฟข้อมูล และแบบฟอร์ม Reading vs Node

🎯 เป้าหมายของบทเรียนนี้: ให้คุณเข้าใจโครงสร้างฐานข้อมูลทั้งหมดของโปรเจกต์นี้แบบคำต่อคำ บรรทัดต่อบรรทัด รู้ว่าทำไมต้องแยกเป็น readings และ nodes และเข้าใจความหมายของศัพท์เทคนิคทั้งหมดด้วยภาษาคนปกติ

1. แปลงศัพท์เทคนิคเป็น "ภาษาคนปกติ"

ก่อนจะเริ่มดูโค้ดจริง ให้จำภาพ 4 คำนี้ไว้ก่อน:

  • Database (ฐานข้อมูล) = ตู้เซฟเอกสารทั้งตู้
  • Collection (คอลเลกชัน) = ลิ้นชักแต่ละชั้นในตู้ (ในโปรเจกต์นี้มีลิ้นชักหลักคือ readings และ nodes)
  • Document (ด็อกคิวเมนต์) = กระดาษบันทึกข้อมูล 1 แผ่นที่อยู่ในลิ้นชัก
  • Schema (สกีมา) = แบบฟอร์มกระดาษเปล่า ที่พิมพ์หัวข้อไว้ว่า "ต้องกรอกอะไรบ้าง ช่องไหนต้องเป็นตัวเลข"
📖 สามารถเปิดดูพจนานุกรมฉบับเต็มได้ที่ GLOSSARY.md

3. ชำแหละไฟล์เชื่อมต่อ: src/db.js (15 บรรทัด)

ไฟล์นี้คือตัวเสียบปลั๊กไฟ เพื่อบอกโปรแกรมว่า "ตู้เซฟ MongoDB อยู่ที่ไหน และเริ่มเปิดประตูเชื่อมต่อ"

โค้ดจริง คำอธิบายภาษาคน
const mongoose = require('mongoose'); เรียกใช้งานเครื่องมือ Mongoose (ผู้ช่วยจัดการตู้เซฟ) เข้ามาในไฟล์
async function connectDB() { สร้างฟังก์ชันชื่อ connectDB โดยมีคำว่า async แปลว่า "งานนี้ต้องใช้เวลารอเชื่อมต่อนะ อย่าเพิ่งรีบข้ามไปทำอย่างอื่น"
const uri = process.env.MONGODB_URI || 'mongodb://127.0.0.1:27017/wildfire_lora'; กำหนดที่อยู่ของตู้เซฟ: ถ้ามีตั้งไว้ในไฟล์ .env ให้ใช้ค่านั้น แต่ถ้าไม่มี ให้เชื่อมต่อไปที่เครื่องของเราเอง (127.0.0.1 พอร์ต 27017) ชื่อตู้เซฟว่า wildfire_lora
mongoose.set('strictQuery', true); สั่งให้ตั้งค่าการค้นหาแบบเข้มงวด ฟิลด์ไหนไม่มีในแบบฟอร์ม ห้ามค้นหา เพื่อความปลอดภัย
await mongoose.connect(uri); คำสั่งเสียบปลั๊กจริง! หมุนกุญแจเปิดตู้เซฟตามที่อยู่ uri โดย await สั่งให้รอจนกว่าจะต่อติดเรียบร้อย
console.log(`connected MongoDB: ...`); พิมพ์ข้อความบอกในหน้าจอดำ (Terminal) ว่าต่อสำเร็จแล้วนะ
module.exports = connectDB; ส่งฟังก์ชันนี้ออกไปให้ไฟล์ server.js เรียกใช้งานตอนเปิดเครื่อง

4. ชำแหละไฟล์สมุดประวัติ: src/models/Reading.js

ไฟล์นี้กำหนด แบบฟอร์มกระดาษ ที่จะบันทึกค่าที่เซนเซอร์ส่งมาทุกรอบ:

โค้ดจริง คำอธิบายภาษาคน
node_id: { type: String, required: true, index: true, trim: true } รหัสเสา ชื่อเสา เช่น "NODE01" ต้องเป็นตัวหนังสือ (String), ห้ามเว้นว่าง (required: true), ตัดช่องว่างหัวท้ายออก (trim), และทำแถบคั่นหน้าค้นหาไว้ (index)
session_id: { type: Number } รหัสรอบเปิดเครื่อง เลขสุ่มตอนบอร์ดเริ่มทำงาน เพื่อแยกว่าบอร์ดถูกรีสตาร์ทใหม่หรือยัง
seq: { type: Number, index: true } ลำดับรอบส่ง เลข 1, 2, 3... นับไปเรื่อยๆ เพื่อให้รู้ว่าส่งเป็นรอบที่เท่าไหร่แล้ว
timestamp: { type: Date, default: Date.now, index: true } วันเวลา เวลาที่บันทึก ถ้าไม่ระบุ ให้เอาเวลา ณ วินาทีนั้น (Date.now)
state: { type: String, enum: ['NORMAL', 'WATCH', 'WARNING', 'SENSOR_FAULT'] } ระดับความเสี่ยง มีคำว่า enum แปลว่า บังคับเลือกได้แค่ 4 คำนี้เท่านั้น! ถ้าส่งคำอื่นมา ตู้เซฟจะไม่ยอมให้บันทึกเด็ดขาด
air_temp: { type: Number } อุณหภูมิ ตัวเลของศาเซลเซียส เช่น 32.5
humidity: { type: Number } ความชื้น ตัวเลขเปอร์เซ็นต์ความชื้นในอากาศ เช่น 45.0
particle_adc: { type: Number, min: 0, max: 4095 } ค่าควัน สัญญาณไฟฟ้าเซนเซอร์ Sharp มีค่าได้ตั้งแต่ 0 ถึง 4095 เท่านั้น ถ้าส่งนอกช่วงนี้จะถูกปฏิเสธ
readingSchema.index({ node_id: 1, session_id: 1, seq: 1 }, { unique: true }); ไม้ตายป้องกันข้อมูลซ้ำ! บรรทัดที่ 34 สำคัญมาก! มันบอกตู้เซฟว่า "ถ้าเสาเดิม รอบเปิดเครื่องเดิม รอบส่งเดิม ห้ามมีแผ่นกระดาษซ้ำในตู้เด็ดขาด!" คลื่นวิทยุ LoRa ส่งมาซ้ำกี่ครั้ง ตู้เซฟก็จะไม่บันทึกเบิ้ล
