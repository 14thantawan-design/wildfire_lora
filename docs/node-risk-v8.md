# เกณฑ์สถานะ Sensor Node รุ่น 8

## หลักการ

Sensor Node เป็นจุดตัดสินสถานะเพียงจุดเดียว Gateway และ Backend ไม่คำนวณความเสี่ยงซ้ำ

ค่าที่ใช้มีสามค่า:

- `T`: อุณหภูมิอากาศจาก SHT31 หน่วย °C
- `RH`: ความชื้นสัมพัทธ์จาก SHT31 หน่วย %RH
- `P`: ความเข้มข้นอนุภาคโดยประมาณจาก Sharp GP2Y1014AU0F หน่วย µg/m³

`P` เป็นค่าประมาณจากแรงดัน ไม่ใช่ค่า PM2.5 ที่สอบเทียบมาตรฐาน

## ลำดับการตัดสิน

```text
ถ้าเซนเซอร์ผิดปกติ
    SENSOR_FAULT
มิฉะนั้น ถ้า T > 45 หรือ P > 150 หรือ (T >= 30 และ RH <= 30)
    WARNING
มิฉะนั้น ถ้า T > 35 หรือ P > 50 หรือ RH < 50
    WATCH
มิฉะนั้น
    NORMAL
```

คำว่า “มิฉะนั้น” สำคัญ เพราะตรวจ `WARNING` ก่อน จึงไม่ทำให้ค่าที่เข้าเงื่อนไขเตือนภัย
ถูกลดเหลือ `WATCH` แม้จะเข้าเงื่อนไข WATCH ด้วย

## ขอบเขตที่ตั้งใจใช้

| ค่า | ผลเมื่อค่าอื่นปกติ |
|---:|---|
| `T = 35°C` | `NORMAL` |
| `T > 35°C` ถึง `45°C` | `WATCH` |
| `T > 45°C` | `WARNING` |
| `P = 50 µg/m³` | `NORMAL` |
| `P > 50` ถึง `150 µg/m³` | `WATCH` |
| `P > 150 µg/m³` | `WARNING` |
| `RH = 50%` | `NORMAL` |
| `30% < RH < 50%` | `WATCH` |
| `RH <= 30%` และ `T < 30°C` | `WATCH` |
| `RH <= 30%` และ `T >= 30°C` | `WARNING` |

ความชื้นเกี่ยวข้องทั้งสองระดับ:

- ต่ำกว่า 50% เพียงอย่างเดียวเป็น `WATCH`
- ไม่เกิน 30% จะเป็น `WARNING` เมื่อเกิดพร้อมอุณหภูมิอย่างน้อย 30°C

## ข้อมูลที่ส่ง

แพ็กเก็ตประกอบด้วยค่าที่วัดได้ `at`, `h`, `pm`, สุขภาพเซนเซอร์ `sh`, สถานะสุดท้าย
`st` และข้อมูลทางเทคนิคที่จำเป็น เช่น `id`, `q`, `sid`, `ri`, `rv` โดยไม่มีคะแนนหรือ
รหัสเหตุผลแบบบิต Gateway ส่งต่อแพ็กเก็ตพร้อม RSSI/SNR และ Backend เก็บสถานะตามที่โหนดตัดสิน

## การยกระดับและลดระดับ

- ยกระดับทันทีจากค่ารอบปัจจุบัน
- `WARNING` ต้องมี 3 รอบติดต่อกันที่ไม่เข้า WARNING จึงลดเป็น `WATCH`
- แม้ค่ากลับปกติทันที `WARNING` จะผ่าน `WATCH` ก่อน
- `WATCH` ต้องมี 3 รอบ `NORMAL` ติดต่อกันจึงลดเป็น `NORMAL`
- ถ้าค่ากลับเข้าระดับเดิม ตัวนับลดระดับจะเริ่มใหม่

## รอบวัด/ส่ง

| สถานะ | `ri` | พฤติกรรม |
|---|---:|---|
| `NORMAL` | 300 | วัดและส่งทุก 5 นาที |
| `WATCH` | 120 | วัดและส่งทุก 2 นาที |
| `WARNING` | 20 | ส่งทันทีและวัด/ส่งทุก 20 วินาที ไม่ Deep sleep |
| `SENSOR_FAULT` | 300 | ตรวจใหม่ทุก 5 นาที |

Backend ถือว่าโหนดออฟไลน์เมื่อไม่มีข้อมูลครบสองรอบรายงานที่คาดไว้ ส่วน Gateway
ทำหน้าที่รับและส่งต่อแพ็กเก็ตโดยไม่เก็บสถานะล่าสุดของแต่ละโหนดซ้ำ

## ข้อจำกัดที่ต้องเขียนในรายงาน

1. งานอ้างอิงหลักใช้ MQ-2 แต่โครงการใช้ Sharp จึงนำตัวเลข MQ-2 raw มาใช้ตรง ๆ ไม่ได้
2. เกณฑ์ 50/150 ถูกใช้กับค่าประมาณจาก Sharp เพื่อให้โครงสร้างสถานะสอดคล้องงานอ้างอิง
   และต้องสอบเทียบ/ทดลองเทียบเครื่องอ้างอิงก่อนอ้างความแม่นยำ
3. เงื่อนไข 30–30 ใช้เพียงอุณหภูมิและความชื้น เพราะโครงการไม่มีเซนเซอร์ลม
4. ระบบนี้เป็นต้นแบบแจ้งสัญญาณบ่งชี้ ไม่ควรอ้างว่าทำนายหรือตรวจไฟป่าได้แน่นอน 100%
5. การส่งทุก 20 วินาทีที่ SF12 ต้องทดสอบ airtime, packet collision และอัตราสำเร็จจริงกับสองโหนด
